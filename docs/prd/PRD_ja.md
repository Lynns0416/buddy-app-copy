## 1. 概要

グループツアーのバディ（ツアーガイド）割り当てを管理するための、社内向けWeb予約アプリです。ユーザーは **バディ**（ツアーガイド）と **管理者**（私たちのチーム）の2種類です。バディはツアーの閲覧・予約・プロフィール管理・自己評価の提出・履歴確認ができます。管理者はツアー・グループ管理・バディの承認・ルール設定・評価を行います。

**主要言語：** 日本語
**対応言語：** 日本語・英語（初日からi18n対応）

---

## 2. 目標・非目標

### 目標
- 既存のGoogleスプレッドシート運用を、構造化されたWebアプリに置き換える
- バディがセルフサービスで予約とプロフィール管理を行えるようにする
- 管理者に完全な可視性・操作権限・通知カバレッジを提供する
- 将来の機能追加・人数増加に対応できるクリーンな基盤を構築する

### 非目標（v1）
- 参加者向け機能（ツアー参加者はこのアプリを使用しない）
- 旅行会社との連携
- ネイティブモバイルアプリ（WebファーストPWA；ネイティブはv1.5以降）
- 高度な分析・レポートダッシュボード
- バディ間のピア評価
- 支払い処理
- カレンダー連携（v1.5で予定）

## 3. ユーザーと役割

| 役割 | 説明 |
|---|---|
| **バディ** | ツアーガイド。ツアーの予約・プロフィール管理・自己評価提出・履歴確認が可能。 |
| **管理者** | 通常の管理者。ツアー・グループ・バディ・予約・評価の管理が可能。 |
| **スーパー管理者** | 通常の管理者権限に加え、管理者アカウント管理とシステム設定が可能。 |

**規模感：**
- ローンチ時：約50名のバディ
- 最大想定：約200名のバディ
- 管理者：少人数チーム（5〜6名、非エンジニア）

## 4. 認証

- **ソーシャルログイン：** GoogleおよびApple（OAuth 2.0）— Firebase Auth使用
- **サインアップフロー：**
  1. バディがGoogleまたはAppleでサインアップ
  2. アカウントが **保留中** 状態で作成される
  3. 管理者に通知が届く
  4. 管理者がアカウントを承認または拒否する
  5. バディに結果が通知される
- **管理者アカウント：** スーパー管理者のみが作成・管理（自己サインアップ不可）
- **セッション管理：** Firebase Authがトークンのライフサイクルを管理

## 5. バディプロフィール

### 5.1 アカウントステータス（管理者管理・管理者のみ閲覧可能）

| ステータス | 説明 |
|---|---|
| **保留中** | サインアップ済み、管理者の承認待ち |
| **研修中** | 承認済み、研修中 — ツアーの予約・リードにはまだ参加不可 |
| **アクティブ** | ツアーの予約・リードが可能な状態 |
| **停止中** | 一時的または恒久的に無効化 |

ステータスは管理者が手動で設定する。標準的な流れ：保留中 → 研修中 → アクティブ。

バディはデータベースから削除されない。停止中のアカウントもすべての履歴とともにDBに保持される。

**研修中の利用範囲：** 研修中バディはログインしてツアー一覧（ステータス数・残席数含む）を閲覧できるが、予約はできない。

### 5.2 内部ティア（管理者管理・バディには非公開）

アクティブになったバディに対して、管理者が手動で内部ティアを設定・更新する：

| ティア | 説明 |
|---|---|
| **ジュニア** | 最近アクティブ化、経験少 |
| **ミドル** | 通常のツアーに慣れている |
| **シニア** | 経験豊富、複雑なグループにも対応 |
| **エキスパート** | 最上位、他のバディのメンタリングも可能 |

内部ティアは管理者専用 — バディには一切表示されない。

### 5.3 バディ自身が編集できるフィールド

| フィールド | 種別 | 備考 |
|---|---|---|
| 表示名 / ニックネーム | テキスト | バディが自由に設定 |
| 本名 | テキスト | 管理者参照用 |
| プロフィール写真 | 画像アップロード | GCP Cloud Storageに保存 |
| 自己紹介 | 長文テキスト | 自由記述 |
| 連絡先情報 | テキスト / メール | 希望する連絡方法など |
| 話せる言語 | 複数選択（enum） | 例：日本語・英語・韓国語など |
| スキル・興味 | 複数選択 + 自由記述 | 例：歴史・スポーツ・音楽など |
| 対応可能日程 | 自由記述 | 一般的な対応可能時間帯など（v1）；将来的に構造化入力へ移行 |

### 5.4 管理者が管理するフィールド

| フィールド | 種別 | 備考 |
|---|---|---|
| アカウントステータス | Enum | §5.1参照 |
| 内部ティア | Enum | §5.2参照 — バディには非公開 |
| 内部メモ | 自由記述 | 管理者のみ閲覧可能 |
| 管理者評価記録 | §9参照 | 管理者のみ |

### 5.5 移行
- ローンチ時に既存のGoogleスプレッドシートからバディデータをインポート
- インポート後、管理者がダッシュボードから不足フィールドを補完
- バディは初回ログイン後に自身のプロフィールを完成させる

## 7. ツアー管理

### 7.1 ツアーフィールド

| フィールド | 種別 | 備考 |
|---|---|---|
| ツアーID | 自動採番 | |
| グループ | グループ参照 | 管理されたグループエンティティに紐づく |
| ツアー日 | 日付 | |
| 集合時間 | 時刻 | |
| 場所 | テキスト | |
| 定員 | 整数 | そのツアーの最大バディ数 |
| 説明 / メモ | 長文テキスト | バディに表示 |
| 管理者メモ | 長文テキスト | **管理者専用 — バディには非表示** |
| キャンセル期限 | 日付 | ツアーごとに設定。バディ個別に上書き可能 |
| 「未定」確認期限 | 日付 | 「未定」バディが確認または辞退する期限 |
| 通知スケジュール | オフセットリスト | ツアー何日前かで指定。デフォルト：3日前・1日前。ツアーごとに設定可能 |
| ステータス | Enum | 下書き / 公開 / キャンセル済 / 完了 |

### 7.2 ツアーステータスのライフサイクル

- **下書き：** 編集可能。バディには表示されない。公開または削除が可能。
- **公開：** アクティブ・研修中のバディに表示される。アクティブなバディのみ予約可能。編集・キャンセル・完了への変更が可能。
- **キャンセル済：** 予約受付終了。確定・未定・補欠のバディ全員に自動通知。以後編集不可。
- **完了：** 予約受付終了。管理者に参加バディへの評価入力を促す。

### 7.3 ルール
- ツアーの作成・編集・キャンセル・完了処理は管理者のみ
- **公開** 状態になるまでバディはツアーを閲覧できない（アクティブ・研修中ともに）
- **アクティブ** なバディのみ予約可能

## 8. 予約システム

### 8.1 予約ステータス

| ステータス | 意味 | 設定者 |
|---|---|---|
| **確定** | 参加確定 | バディ |
| **未定** | 仮参加。管理者設定の期限までに確認が必要 | バディ |
| **補欠** | 空きが出た場合のみ参加希望 | バディ |
| **辞退** | 参加しない・キャンセル | バディまたは管理者 |

### 8.2 席数の表示

バディはツアーごとの全ステータス数（確定・未定・補欠・辞退）を確認できるが、誰が予約しているかは見えない。

**残席数** = `定員 − 確定数`。確定のみが定員を消費する。未定・補欠は席を消費しない。

### 8.3 予約ルール

- バディはツアーごとに **1つのステータス** のみ保持できる
- **アクティブ** なバディのみ予約可能
- ツアーが公開中かつキャンセル期限が過ぎていない間は予約可能
- 管理者はバディ個別にキャンセル期限を上書きできる

### 8.4 ステータス遷移マトリクス

| 遷移元 \ 遷移先 | 確定 | 未定 | 補欠 | 辞退 |
|---|---|---|---|---|
| 確定 | — | ✅ | ✅ | ✅（期限前） |
| 未定 | ✅ | — | ✅ | ✅ |
| 補欠 | ✅ | ✅ | — | ✅ |
| 辞退 | ✅ | ✅ | ✅ | — |

キャンセル期限前はすべての遷移が可能。期限後は管理者のみがステータスを変更できる。

### 8.5 「未定」フロー

1. バディが予約時に「未定」を選択
2. 管理者がツアーごとに **確認期限** を設定（未設定の場合はデフォルトのオフセットを適用 — ツアー3日前；グローバル設定で変更可能）
3. 期限が近づくとバディに通知リマインダーが届く
4. バディは期限前に **確定** または **辞退** に更新する必要がある
5. 期限までにアクションがなかった場合、管理者にフォローアップ通知が届く

### 8.6 「補欠」フロー

1. バディが「補欠」を選択
2. キャンセルで空きが出ると、補欠バディ全員に同時通知が届く
3. バディは手動でステータスを **確定** に更新して席を確保する
4. 先に確定したバディが優先 — 自動割り当てなし

> **注：** 同時申請時のタイブレーカーポリシーは未決定。サーバーは同時確定リクエストをアトミックに処理し、オーバーブッキングを防止する必要がある。未解決事項を参照。

### 8.7 キャンセルとキャンセル理由

- バディはキャンセル期限までステータスを「辞退」に変更できる
- **確定から辞退へのステータス変更時**（バディ・管理者いずれが変更した場合も）、**キャンセル理由** の記録が必須
- キャンセル理由フィールド：

| フィールド | 種別 | 備考 |
|---|---|---|
| 理由カテゴリ | Enum | 体調不良（病気・怪我）/ 個人的事情 / 業務都合 / その他 |
| 自由記述 | テキスト | カテゴリが「その他」の場合は必須；それ以外は任意 |
| やむを得ないフラグ | Boolean | カテゴリに基づいて自動設定；管理者が上書き可能 |
| 記録者 | ユーザー参照 | 自動入力（バディまたは管理者） |

- **体調不良**（病気・怪我）は自動的に「やむを得ない」としてフラグが立ち、信頼性指標の計算から除外される
- 管理者はいずれの理由に対しても「やむを得ない」フラグを手動で上書きできる
- キャンセル理由のカテゴリEnum値は未決定（上記はプレースホルダー）；開発前に確定する

期限後のキャンセルは管理者のみが実行可能。その場合も理由の記録は必須。

### 8.8 予約履歴

- 過去の全予約（ステータス含む）はバディごとに永続的に保存される — 削除されない
- 履歴は継続的に増加する — DB設計で考慮が必要
- 管理者は任意のバディの予約履歴を閲覧できる
- バディは自分自身の予約履歴のみ閲覧できる

## 9. 評価システム

### 9.1 概要

評価には2種類ある：**管理者評価**（内部のみ、バディには非公開）と **バディ自己評価**（バディ本人と管理者が閲覧可能）。

### 9.2 管理者評価

#### 評価タイプ

| タイプ | タイミング | 備考 |
|---|---|---|
| **ツアー別評価** | 特定のツアー後 | ツアーレコードに紐づく |
| **プロフィール全般評価** | 随時 | 特定のツアーに紐づかない |

#### 評価フィールド（v1、後日精緻化予定）

| フィールド | 種別 | 備考 |
|---|---|---|
| 総合評価 | Enum | 例：優秀 / 良好 / 普通 / 要改善（プレースホルダー） |
| 信頼性 | Enum | 選択肢は後日定義 |
| コミュニケーション | Enum | 選択肢は後日定義 |
| グループへの関わり方 | Enum | 選択肢は後日定義 |
| 自由記述コメント | 長文テキスト | 自由記載 |
| 評価者 | 管理者参照 | 自動入力 |
| 評価日 | 日付 | 自動入力 |

> **注：** 具体的なEnum値は開発開始前にチームで定義します。

#### アクセス権限
- 評価の作成・閲覧・編集は管理者のみ
- バディは管理者評価を閲覧できない

#### 評価プロンプト
- 管理者がツアーを **完了** にマークした際、参加バディの一覧が表示される
- 管理者は評価するバディを選択する（一部または全部をスキップ可能）
- プロンプト全体をスキップすることも可能

### 9.3 バディ自己評価

#### タイミング
- ツアーが **完了** にマークされると、バディに自己評価の入力を促す通知が届く
- プロンプトはオプション — スキップ可能

#### 評価フィールド（v1、後日精緻化予定 — プレースホルダー構成）

| フィールド | 種別 | 備考 |
|---|---|---|
| 総合自己評価 | Enum | 例：優秀 / 良好 / 普通 / 要改善（プレースホルダー） |
| うまくいったこと | 長文テキスト | 自由記述 |
| 改善できること | 長文テキスト | 自由記述 |
| 評価日 | 日付 | 自動入力 |

#### アクセス権限
- バディは自分の自己評価を提出・閲覧できる
- 管理者はすべてのバディの自己評価を閲覧できる
- バディは他のバディの自己評価を閲覧できない

## 10. 通知

### 10.1 バディへの通知

| イベント | チャネル | タイミング |
|---|---|---|
| 新規ツアー公開 | アプリ内 + メール | 公開直後 |
| ツアーリマインダー | アプリ内 + メール | ツアーごとに設定可能。デフォルト：3日前・1日前 |
| 「未定」確認期限リマインダー | アプリ内 + メール | 設定可能。確認期限前にトリガー |
| 補欠席が空いた | アプリ内 + メール | キャンセル直後 |
| アカウント承認 / 拒否 | メール | 管理者の判断直後 |

### 10.2 管理者への通知

各管理者はイベントごとに通知チャネルと配信モードを個別に設定できる。

| イベント | 利用可能チャネル | デフォルトタイミング |
|---|---|---|
| 新規バディサインアップ（承認待ち） | メール および/または Slack | 即時 |
| 新規予約 | メール および/または Slack | 後述参照 |
| 予約キャンセル（確定 → 辞退） | メール および/または Slack | 即時 |
| 未定 → 確定または辞退 | メール および/または Slack | 即時 |
| 「未定」期限切れ（未対応） | メール および/または Slack | 期限到達時 |

**メール配信モード（管理者・イベントごとに設定可能）：**
- **即時：** イベント発生時にメールを送信
- **日次ダイジェスト：** 毎朝9時に前日の活動をまとめて送信。活動がなかった日は送信しない

**デフォルトのメール配信モード：**
- キャンセルおよび未定の解消：即時
- 新規予約・新規サインアップ：日次ダイジェスト

Slack通知は有効な場合、常に即時送信。

**チャネル設定：** 各管理者はアカウント設定でイベントごとに通知チャネル（メール・Slack・両方）と配信モード（即時またはダイジェスト）を個別に設定できる。

## 11. 管理ダッシュボード

### 11.1 バディのホーム画面

バディがログインすると以下が表示される：
- 公開中の今後のツアー（ステータス数・残席数含む）
- 自分の現在の予約一覧とステータス
- プロフィールと履歴へのアクセス

### 11.2 ツアー管理
- ツアーの作成・編集・公開・キャンセル・完了処理
- ツアーごとの予約一覧（バディ名・ステータス・予約日時）
- キャンセル期限の設定と上書き（ツアー単位・バディ個別）
- 「未定」確認期限の設定
- ツアーごとの通知スケジュール設定
- 管理者専用メモの追加・編集

### 11.3 グループ管理
- グループの作成・編集
- グループのツアー履歴閲覧
- 連絡先情報とメモの管理

### 11.4 バディ管理
- 全バディプロフィールの詳細閲覧（ステータス・ティア・管理者評価・自己評価含む）
- サインアップの承認・拒否
- アカウントステータスと内部ティアの設定・更新
- 管理者管理フィールドの編集
- バディごとの予約履歴閲覧
- 管理者評価の登録・閲覧

## 14. データ移行

- **移行元：** Googleスプレッドシート（バディプロフィールデータ）
- **対象：** ローンチ時はバディプロフィールのみ
- **プロセス：**
  1. GoogleスプレッドシートをCSVにエクスポート
  2. フィールドをPrismaスキーマにマッピング
  3. 一回限りのインポートスクリプトを実行
  4. 管理者がダッシュボードから不足フィールドを確認・補完
  5. バディが初回ログイン後にプロフィールを完成させる
